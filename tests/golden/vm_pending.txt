# Golden tests that do not pass on the bytecode VM yet (COLIBRI_ENGINE=vm).
#
# One test per line: `path  # reason`, the reason being the feature the VM lacks. A folder
# test ends with `/`. A listed test is reported as ignored; a listed test that passes fails
# the run, so delete its line when it starts to pass. Regenerate the whole list with
#   COLIBRI_ENGINE=vm COLIBRI_VM_PENDING_REPORT=1 cargo test -p colibri-lang --test golden
# only when a step lands that makes many tests pass at once.
#
# Tests that only run on one system (`// only: windows`) are listed too, so `both` and the VM run
# on that system see them as pending; here they are ignored and the ratchet leaves them be, but a
# path that names no test still fails. Their reasons were taken from the same program run on Linux
# with the `only:` line removed, and from the twin for the other system. The regeneration above
# skips them: add or keep them by hand. Three are not listed because the VM now runs them as far as
# the tree-walker does on Linux: `std/path_from_native_windows` and `std/path_roots_windows` (step
# 6 supports `match`), and `ffi/libc_windows_integers` (`extern` is supported; only `_getpid` is
# missing here, as for the tree-walker). Four more are not listed since step 8:
# `std/process_error_failed_windows`, `process_shell_windows`, `process_spawn_windows` and
# `process_windows` need no feature the VM lacks (their reasons were built-ins; `cmd` is missing on
# Linux, so the gate-lifted run stops early). A copy of `process_spawn_windows` and `process_windows`
# with `sh`, `grep` and `sleep` in place of `cmd`, `findstr` and `ping` ran to the end with the same
# output on both engines. The Windows CI run is the proof.
